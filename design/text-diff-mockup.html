02差异的四种展现（放大 1.6 倍细看）

三类差异各用一条「底 + 左缘条 + gutter 标记」的三重线索，词级再叠一层文字装饰。 关键取舍：**正文一律保持 -dt-text（≈17:1），颜色只出现在行底、左缘条、gutter 标记这三处**。 大面积文本着色会让整页变成彩纸，长时间阅读时反而不如黑白清楚 —— 差异是靠位置与标记读出来的，不是靠颜色读出来的。

删除只存在于原文的行

整行是「被拿掉的东西」，站在原文这一侧才有意义。

−9db_pool = 10
  • 行底 #fdeeee，左缘 3px -dt-danger 实心竖条
  • gutter 标记 −，行号 加粗转危险色（不只靠底色）
  • 对应的修改后一侧补一条**斜纹占位行**：行数对得上，横向扫视才不会错位
  • 文字不加删除线 —— 删除线留给词级，行级用条与标记已经够

新增只存在于修改后的行

与删除完全对偶，只是换了色相与标记 —— 学一次就会用。

+8tls_enabled = true
  • 行底 #eaf6ef，左缘 3px -dt-success 实心竖条
  • gutter 标记 +，行号加粗转成功色
  • 新增行**不写删除线也不写下划线**：它是纯粹的「多出来的」，没有可对比的旧值
  • 行数变化时，原文一侧自动补占位行（图为原文侧）

修改两侧成对、行内改了几处

最难表达的一类：不是「多了一行」也不是「少了一行」，而是一行被换掉了内容。

~3port = 8080
~3port = 9090
  • 行底换成中性的 #fdf7ec（不偏红也不偏绿），左缘用 上红下绿的双色条 —— 一眼看出「这一行两端都动过」
  • gutter 标记 ~，行号加粗转警告色
  • 行内再把词级差异叠上去：左侧旧值 删除线 + 淡红底，右侧新值 下划线 + 淡绿底
  • 删除线 vs 下划线是两种形状而不是两种颜色 —— 色觉障碍用户与黑白截图里同样读得出
  • 只有把「行级配对」做出来，修改才可能是一种独立展现；否则它会被拆成一对删除 + 新增，三态退化成两态（见 §6）

04设计规范

A. 新增令牌（差异域，加在 app.css 的 .root 里）

令牌值用途为什么
-dt-diff-add-bg#eaf6ef新增行底成功色的浅底版。与白底差异约 5%，够看见又不压过正文
-dt-diff-add-word#c8e9d6新增词底必须比行底再深一档，否则行内词级差异在一行里看不出来
-dt-diff-del-bg#fdeeee删除行底与 -dt-danger-soft 同族，略作提亮以免与错误提示条混淆
-dt-diff-del-word#f7d2d3删除词底同上
-dt-diff-mod-bg#fdf7ec修改行底暖中性色，既不是红也不是绿 —— 修改既不是「多了」也不是「没了」
-dt-diff-mod-word#fbe6c8修改词底（可选）粒度选「按词」时，未配对的零散词用这档；成对替换仍用上面两个词底
-dt-diff-gutter#f4f6f9行号列底比 -dt-surface-alt 略沉，把「行号」与「正文」分开，但不形成第二张卡片的边界
左缘 3px 色条与 gutter 标记不新增令牌，直接引用 -dt-success / -dt-danger / -dt-warning：这三个色对白底的对比度都在 5:1 以上，远超非文本图形 3:1 的门槛，换主题时也会跟着走。

05关键决策：为什么是这样

决策理由
中间列不显示第三份文本 三份文本会让人在三列之间来回对照，眼睛要做两次跳转。判断「这处改得对不对」的锚点永远在原文与结果上，所以差异必须画在两侧的行上；中间列只回答三个问题：有多少 · 在哪里 · 是什么。这是三列能比双列多给出东西的唯一理由。
把「修改」做成独立的第三类 纯行级 diff 会把 port = 8080 → 9090 拆成一删一增，屏幕上同时出现红行与绿行，用户得自己判断它们是不是同一行。做一次行级配对 + 行内词级比对，把它合成一个「修改」态，三类差异才真正可区分 —— 这也是「新增/修改/删除分别用不同展现」能够成立的前提。
正文不着色 颜色只出现在行底、左缘条、gutter 标记三处。大面积文本着色会让整页变成彩纸，长时间阅读时反而不如黑白清楚；且改为「位置 + 标记」表达后，色觉障碍用户与灰度截图里同样读得出差异。与既有纪律「颜色永不是唯一线索」一致。
修改行底用暖中性色 + 双色条 红与绿在本页已经分别代表「没了」和「多了」。修改既不是多了也不是没了，用第三种底色；左缘条上红下绿，一眼看出「这一行两端都动过」。若给它一个红底或绿底，用户会误判成单纯的删除或新增。
缺失一侧必须有斜纹占位行 两侧行数不等时若不补行，下面的所有行都会错位，横向扫视彻底失效。占位行用斜纹而不是留白：留白会被读成「这里本来就空着」，斜纹明确表示「这一侧没有对应行」。
变更图是「密度图」而不是「缩略图」 只画条、不画文字缩略 —— 220px 宽度下文字缩略只能变成一片灰噪点。编码两件事就够：纵向位置 = 在文档中的位置，横向条长 = 该组变更的行数。视口指示框只在内容超出视口时出现——100% 时它等价于整块区域本身，画出来只是套了个圈。
空态分两处 两侧是可输入区域 → 用 promptText（居中大图标会挡在用户马上要打字的地方）；中间列是整块内容区 → 用统一空状态组件。这条分工沿用既有规范，不新造规则。
工具条用内联 checkbox 而不是选项卡片 本页垂直空间要全部让给文本区（三列都需要高度），选项卡片会吃掉约 90px，等于少看 4 行。这是对既有「选项放卡片」做法的一次有意偏离，理由是页面形态不同：文本处理页是「上输入下输出」，本页是「三列并列」。
不新增第五种颜色 差异域的颜色全部来自既有的成功 / 警告 / 危险三色阶，只是取浅底与深色两种用法。加新色相会让整页的色相数量失控（对照禁忌项「给卡片墙加彩色图标底托」）。

JavaFX 实现三处细节 ① 修改行的双色左缘条：一个 3px 宽的 Region，-fx-background-color: -dt-danger, -dt-success + -fx-background-insets: 0 0 50% 0, 50% 0 0 0；
② 斜纹占位行：-fx-background-color 叠两层线性渐变模拟 45° 斜纹（JavaFX 无 repeating-linear-gradient），或退化为 -dt-surface-sunken 纯色底 —— 两个方案都做进探针截图对比后取一；
③ 每行是固定 20px 的 HBox（-fx-pref-height 与 -fx-min-height 必须成对），行内 Label 用 FlowPane 或者等宽 TextFlow 才能承载词级 span。
探针 verify.cmd diff（纯逻辑）：三类归类、左右行号、词级区间、占位行对齐、三种忽略规则。
verify.cmd diffui（界面级）：断言三个计数互相咬合 ——「差异组数 == 中列清单条目数 == 变更图上的条数」，且「左栏行数 == 合并行中非新增行数」。任一处丢数据都会被这三条交叉断言抓到（参照 qrlist 对「不丢数据」的做法）。新增断言必须做反向验证。

出图前想请你定的三件事

  1. 粒度默认值：图里默认「按词」（行级已配对的前提下，词级才有东西可标）。若你更关心整段结构变化，默认改成「按行」更安静 —— 两栏里只有行级高亮。
  2. 要不要「统一视图」（单列 unified diff）：我倾向不做。三列已经把阅读方式固定成并排，再加一种视图会稀释它；但「复制差异」导出的仍是标准补丁格式，需要单列时去看补丁即可。
  3. 中列 220px 够不够：如果你常在小窗口（≤ 1024px）里用，中列可以折叠成 44px 的纯密度图条，需要清单时再展开。要的话我出这一版的折叠状态图。
