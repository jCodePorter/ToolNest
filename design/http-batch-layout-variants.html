02为什么结果区必须整宽 —— 把算术摊开

结果表不是「可大可小的一块」，它的最小宽由每条列的最小信息量加出来：520px。一旦把结果区切窄，缺的这段就只能靠横向滚动补 —— 而横向滚动比纵向滚动更难用（列头随之滚走）。

结果表最小必需宽 = 520px 的来历（列宽尺，1:1）

结论：把结果区压窄不是解决拥挤，而是把「纵向被压」换成「横向被压」—— 地址 与 响应预览 会被推出视口，而它们正是判读结果的依据。 横向与纵向是同一笔预算的两端：结果区变窄，只是把「纵向看不见的行」换成「横向看不见的列」。 因此结果区应当永远占整幅内容宽（950），「省纵向」要靠在输入区做折叠 / 页签，而不是靠切窄结果区。
