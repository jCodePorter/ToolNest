### 修掉的缺陷（每条都在真实字节流或运行态上验证过）

| 级别 | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| P0 | 切走再切回 HTTP 页，Send 永久卡在「发送中…」点不动 | `SingleRequestPanel.executor` 是 final 单例，`scene==null` 触发 `shutdown()` 关池，而 `ContentPane.detailCache` 复用同一节点 → 再 submit 抛 `RejectedExecutionException` | 池改懒创建 + `shutdown()` 置 null；`submit` 外包 catch 复位按钮 |
| P0 | GBK 接口响应全乱码 | `BodyHandlers.ofString(UTF_8)` 强制按 UTF-8 解码，而中文接口不声明 charset 是常态 | 改收 `byte[]`，先读 `Content-Type; charset=`，取不到再探测（严格 UTF-8 → GBK 兜底） |
| P0 | 导出结果 CSV 在 Excel 里中文乱码 | `Files.writeString(..., UTF_8)` 不带 BOM，中文 Windows 的 Excel 按 GBK 解 | 写盘前加 `\uFEFF`；`CsvParser.readText` 读回时剥掉 BOM，闭环 |
| P1 | 请求头里的 `{列名}` 不替换，原样发出去 | `runBatch` 把 `headersTable.entries()` 直接交给引擎，而界面与 `description()` 都声明支持请求头占位符 | 每行按 CSV 变量替换键与值存进 `ResultRow.headers`，详情面板展示替换后的实际值 |
| P1 | 导出的「状态」列写 -1 | 用了 `status()` 而非 `stateText()`，未执行行在表格里是「等待中」，导出却像失败 | 改用 `stateText()` |
| P1 | `finalUrl` 不反映重定向 | 用的是发请求前拼的地址 | 改用 `response.uri()` |
| P1 | 选了「无请求体」却填了 JSON，请求静默不带 body | `hasBody()` 只看 `bodyType != NONE` | 新增 `HttpRequestSpec.inferBodyType`（NONE + 非空内容按形状判 JSON/TEXT），两个页面共用 |
| P1 | 响应预览每次表格刷新都重跑空白折叠正则 | `responsePreview()` 无缓存，而 `resultTable.refresh()` 会重算所有可见行 | 预览在 `setResult()` 时算一次存下来 |

顺手清理：`HttpEngine.hasHeader` 的死参数；`mergeQuery` 忽略 URL fragment（参数被拼到 `#` 之后整段丢掉）；`SingleRequestPanel` 的占位符检查不含 Body；响应「大小」改用真实字节数而非重新按 UTF-8 估的。

### 新探针 httpfix（32 断言）+ TinyHttpServer
- `TinyHttpServer`：ServerSocket 手写的最小 HTTP 服务。**故意不用 `com.sun.net.httpserver`** —— 它不在默认模块根集合里，要跑得给 java 加 `--add-modules jdk.httpserver`，会牵动 verify.cmd。手写还能精确造「Content-Type 声明 GBK」「302 跳转」这类真实场景
- 引擎侧断言全部跑在真实 socket 上（编码 / 重定向 / POST body / 请求头），不打桩
- **反向验证抓出探针自身的假阳性**：线程池是懒创建的，探针不先提交一次就直接 `shutdown()`（此刻池还是 null），「切回后仍能提交」这条断言其实恒真。补上「先提交一次」的前置后才真正变红。**教训：恒真的断言比没有断言更危险** —— 它会让人以为覆盖到了

### 红框 A（段①②头带右端箭头）= 折叠失效
- 根因：`CollapsibleSection` 构造器参数名 `expanded` **遮蔽**了同名字段，而头带点击 lambda 写在构造器里 → 读到的永远是参数 `true`
- 症状：`setExpanded` 值序列 `[false,false,false,false]` —— ①永远只收起、②永远只展开，点一次管用、再点没反应，**编译期一声不响**
- 修法：参数改名 `startExpanded` + 处理器写 `!this.expanded` 双保险（注释里写清成因）

### 红框 B（执行条「线程数 [8] 超时 30 秒 间隔 0 ms」）= 降级态只做了 setDisable
- 实测像素（用户截图）：**线程数标签 (90,96,104) 与「超时」标签完全一致（全黑未降级），而数值 (209,211,215) 只有 17% 墨迹**
- 判定依据是设计稿的不变量，`design/http-batch-redesign.html` §06-5 原文：
  「**整行降透明（42%）+ 明写原因**」「**颜色永不是唯一线索**」「禁用态必须配文字，**不能只做 setDisable**」
- 修法：`UiKit.setDegraded(target, note, degraded)` + `UiKit.degradeNote(text)`
  - 整组 42% 透明度（**不调 setDisable**：它只压被禁的那一个子节点，还会额外灰掉输入框表面）
  - 交互改用「不吃鼠标 + 不进 Tab 序 + 编辑器只读 + KeyEvent 拦截器兜底」（拦截器只挂一次）
  - 原因文字 `并发时生效`（`-dt-warning` #a1590a，12px，新样式类 `.degrade-note`）
- 同一不变量的另两处一起收：批处理页/单一请求页的「请求体类型 = NONE」降级态（原来只有 `setDisable + opacity 0.5`、零文字）
  - 批处理页的说明**内联挂在「请求体类型」那一行右侧**，不新增一行 —— 段①竖向预算刚好卡在 653 一屏内，多 20px 就要整页滚动
