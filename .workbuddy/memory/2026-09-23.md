### 后续修复（同日 11:30）

用户执行 `.\build.cmd javafx:run` 报 `'EM' 不是内部或外部命令` 等一连串错位错误。

**根因**：`.cmd` 批处理文件里写了中文（注释和 echo）。cmd.exe 按系统 ANSI 代码页
（中文 Windows = GBK）解析 .cmd 文件，而文件是 UTF-8 存的，中文三字节序列的
第二字节被当成 GBK 尾字节，吞掉后面的换行和下一个命令的首字符，
于是 `REM` → `EM`、`set JAVA_HOME` → `AVA_HOME`，整份脚本错位。

**修复**：`build.cmd` 和 `package.cmd` 重写为**纯 ASCII**（注释和输出全改英文）。

**教训 / 项目约定**：
> 本项目所有 `.cmd` / `.bat` 文件必须保持纯 ASCII，禁止出现中文。
> 中文只放在 `.java`、`.md`、`.css` 里（这些由 Maven 按 UTF-8 读取，没问题）。

**同时修正的一处严重错误**：排查时我误判了包名。
实际源码在 `src/main/java/com/bytefuture/desktool/`，包名 `com.bytefuture.desktool`。
但 `pom.xml` 的 javafx-maven-plugin `mainClass` 和 `package.cmd` 的 `MAIN_CLASS`
一度被改成了不存在的 `com.desktool.*`，导致 `javafx:run` 报
`找不到或无法加载主类 com.desktool.DeskToolApp`。已全部改回：

| 位置 | 正确值 |
|---|---|
| pom.xml `main.class` 属性 | `com.bytefuture.desktool.Launcher` |
| pom.xml javafx-maven-plugin | `${main.class}`（用属性引用，避免不一致） |
| pom.xml groupId | `com.bytefuture` |
| package.cmd MAIN_CLASS | `com.bytefuture.desktool.Launcher` |

**改包名时记得同步的地方**：pom.xml 的 `main.class` 属性 + package.cmd 的 MAIN_CLASS。
建议始终用 `${main.class}` 属性引用，只维护一处。

**最终验证（全部通过）**：
- `build.cmd` → fat jar 10MB，MANIFEST `Main-Class: com.bytefuture.desktool.Launcher`
- `build.cmd javafx:run` → 窗口 `DeskTool 工具箱` 正常弹出，无报错

**注意**：`build/dist` 目录被沙箱保护，不能直接 `Remove-Item` 删除，

### 新增功能：HTTP 请求工具（同日 12:52-13:05）

用户要求：单一请求 + 批处理；批处理支持上传 CSV 取参数、替换接口与参数中的占位符、
支持 GET/POST/PUT/DELETE。参考截图是 Postman 的 Params 面板。

**用户通过 AskUserQuestion 确认的决策**
| 问题 | 选择 |
|---|---|
| CSV 格式约定 | **表头即变量名** |
| 并发/顺序 | **支持配置，两者都要** |
| 占位符语法 | **只用单花括号 `{列名}`** |
| CSV 导入方式 | **选文件 + 粘贴文本，两种都要** |
| 结果展示 | **表格 + 可导出 CSV** |
| 单一请求范围 | **URL + Params + Headers + Body** |

**新增 `ModuleCategory.NETWORK`**（"网络请求工具"，图标 `\u21AF`），插在 TEXT 与 IMAGE 之间。

**新增 8 个类（`modules/http/`）**
- `HttpRequestSpec` —— 请求值对象：Method 枚举（带 `allowsBody()`）、
  BodyType 枚举（NONE/JSON/FORM/TEXT/XML，各带 contentType）、url/body 字段
- `HttpEngine` —— 基于 `java.net.http.HttpClient`（静态单例，NORMAL 重定向，15s 连接超时）。
  `Result` 内含 status/elapsedMs/headers/body/finalUrl/requestBody/error，带 `statusClass()`
  供 UI 着色。`mergeQuery()` 把 Params 表合并进 URL（保留 URL 自带查询串，用 `&` 连接）
- `TemplateResolver` —— `{列名}` 替换，**列名匹配忽略大小写**；
  未匹配到的占位符**原样保留**（便于发现拼写错误，不静默替换成空）；
  提供 `placeholders()` / `unresolved()` 供预检
- `CsvParser` —— 零依赖 CSV 解析：分隔符自动识别（逗号/分号/制表符，按首行计数取最多）、
  引号包裹与 `""` 转义、引号内换行、空行跳过、**编码自动识别**（BOM→UTF-8；
  否则用 `CodingErrorAction.REPORT` 严格解码试探，失败回退 GBK）
- `KeyValueTable` —— 可复用键值对编辑表（Params/Headers 共用），
  带勾选框控制是否参与、尾部自动保留空行、`setOnRowsCountChanged()` 回调刷新 Tab 角标
- `SingleRequestPanel` —— 单一请求面板（仿 Postman）
- `BatchPanel` —— 批处理面板（4 步式布局：①请求模板 ②CSV数据 ③执行配置 ④执行结果）
- `HttpToolModule` —— 模块入口，TabPane 装两个面板

**占位符语法的实现细节**：主用 `{x}`，但 `TemplateResolver.normalize()` 会先把 `{{x}}`
归一化为 `{x}`，这样两种写法都能用且不会互相干扰。

**踩的坑**
1. `HttpEngine.send(spec, headers, timeout)` 调用少传了 params 参数（4 参重载），编译报错
2. `Result.elapsedMs` 是基本类型 `long`，我错写成 `elapsedMs.equals(0L)` → 编译报"无法取消引用long"
3. **`ConnectException` 提示不友好**：`describe()` 只匹配 message 关键字，
   但 JDK 的 `UnresolvedAddressException` / `ConnectException` 的 **message 全为 null**！
   排查方式：写 `RawErr.java` 打印完整 cause 链，发现 `ConnectException → ConnectException
   → UnresolvedAddressException`。修复：新增 `collectTypes()` 汇总 **cause 链的类名** 一起匹配，
   不能只靠 message。
4. **Git Bash 下 javac/java 的 classpath 陷阱**：用 `/d/Dev/...` 这种 MSYS 风格路径，
   Windows JDK 读不到（会报"程序包不存在"）。必须用 `D:/Dev/...` Windows 风格路径，
   并加 `MSYS2_ARG_CONV_EXCL="*"` 阻止 MSYS 二次转换。

### JSON 格式化增强：语法高亮 + 缩进自动重排（同日 13:41-13:50）

用户要求：① JSON 格式化结果加颜色高亮；② 切换缩进后自动重新格式化。

**技术选型（经 AskUserQuestion 确认）**

**新增 `ui/JsonCodeArea.java`**
- `extends CodeArea`，泛型是 `StyleSpans<Collection<String>>` —— RichTextFX 用
  「一组样式类名」表示区间样式，颜色最终由 CSS 决定，所以配色写在 app.css
- 单条大正则 + 命名捕获组一次性分词（KEY/STRING/NUMBER/KEYWORD/PUNCT）
- **键名识别技巧**：正则里把 KEY 定义为「字符串 + 紧跟的冒号」，且放在 STRING 分支**之前**，
  这样 `"code":` 会被先匹配成 KEY 而不是 STRING。但冒号要按标点着色，
  所以在代码里把该分组再拆成「引号内键名」+「冒号」两段分别上色
- 禁用编辑 + `getUndoManager().forgetHistory()`，但保留选中复制能力

**RichTextFX 的 4 个 API 坑（重要）**
1. **`StyleSpansBuilder.add(S, int)`** —— 第二个参数是「长度」不是样式；
   旧写法 `add(Collections.singleton(style), len)` 会因泛型不匹配编译失败
2. **`StyleSpans.create()` 不存在** —— `create()` 在 `StyleSpansBuilder` 上
3. **`CodeArea` 没有 `setPromptText`** —— 它不是 `TextInputControl`，
   占位文字要用 `setPlaceholder(Node)`，我封装成 `setPlaceholderText(String)`
4. **span 长度之和必须等于文本长度**，否则 RichTextFX 抛异常。
   空文本也要 `add(emptyList(), 0)` 给一个空 span

**缩进自动重排的实现要点**
- 用 `enum Action {FORMAT, MINIFY, ESCAPE, UNESCAPE}` + `lastAction[0]` 记住上次操作，
  **只在 `lastAction == FORMAT` 时才自动重排**
- 原因：压缩结果是一行、转义结果是字符串字面量，给它们套缩进毫无意义甚至破坏内容。
  这个判断不做的话，用户在「压缩」后切缩进会得到莫名其妙的结果

**关键踩坑（务必记住）**
1. **JavaFX CSS 不支持 Web CSS 的自定义属性**。写 `--x: value` + `var(--x)`
   会静默失效并刷屏 `Could not resolve` / `ClassCastException: String cannot
   be cast to Paint`。必须用 JavaFX 的**命名颜色（looked-up colors）**：
   在 `.root` 里定义 `-dt-accent: #2563eb;`，别处裸写 `-dt-accent`。
   命名颜色只能装颜色；间距/圆角/字号/高度必须写字面量。

## Bug 修复：CSV 文本编辑框首行多一个空心方框（BOM 未剥离，同日 17:35）

**现象**：HTTP → 批处理页，选 `工作簿1.csv` 后，② 区「CSV 数据」的**文本编辑框**里
首行显示成 `□name,age,city,area`（多一个空心方框）；下方预览表头正常。

**根因**：文件是 **UTF-8 with BOM**（首字节 `EF BB BF`）。
`BatchPanel.chooseCsvFile()` 用 `Files.readString(path, UTF-8)` 直接塞进 `csvArea`，
**没有剥 BOM** → `U+FEFF` 留在字符串开头 → JavaFX 渲染成空心方框 `□`。
（`CsvParser.parse()` 第 79-82 行本来就剥了 BOM，所以**预览表格是对的、只有编辑框脏**。
两个入口处理不一致才是真正的 bug 所在。）

**修复**
- `CsvParser` 新增两个公开方法，**统一 BOM 处理**：
  - `readText(Path)` —— 自动识别编码读文件文本 + 剥 BOM
  - `stripBom(String)` —— 剥 `U+FEFF`（null 安全）
  - `parse(String)` 改为复用 `stripBom`；`parseFile` 改为复用 `readText`
- `BatchPanel.chooseCsvFile()` 改用 `CsvParser.readText()`（顺便消掉原来重复读文件两次），
  文本与解析结果同源，**显示与解析保证一致**
- `BatchPanel.parseFromTextArea()` 加注释说明粘贴路径同样会剥 BOM

**验证**
- `BomProbe`（纯逻辑，20 项断言全 PASS）：含「旧写法确实残留 FEFF」这一对照项，
  直接证明 bug 成因；覆盖 null / 空前缀 / 中间 BOM 不误删 / 只剥第一个 /
  无 BOM 文件回归 / GBK 文件回归
- `BomRenderProbe`（真实 BatchPanel + 真实文件 + 真实 Stage + snapshot）：
  `csvArea` 首字符 = `n`（U+006E），`startsWithFeff=false`，4 列表头 code point 全干净
- 截图：`build/preview/bom-1_file_loaded.png`（方框消失）、`bom-2_pasted_bom.png`

**踩坑（重要，反复踩）**：`mvn` 编译突然满屏 `未结束的字符串文字` 报错，
涉及 `DesignPreview.java` / `EncodeModule.java` / `BatchPanel.java` 等多个**我并未修改**的文件。
误以为源码被写坏。实际原因是 **shell 里 `JAVA_HOME=C:\Program Files\Java\jdk-1.8`**（指向 JDK 8），
我这次直接调 `mvn.cmd` 时没像 `build.cmd`/`package.cmd` 那样显式覆盖 JAVA_HOME，
Maven 用 JDK 8 编译 Java 21 源码 → 全线崩溃。

> **项目约定**：在 Git Bash 里直接跑 Maven，必须显式覆盖 JAVA_HOME：
> `JAVA_HOME="C:/Program Files/Java/jdk-21" mvn ...`
> 只看「一堆奇怪语法错误」别急着改代码，先 `echo $JAVA_HOME`。
